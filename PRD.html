Propel genera la propuesta Full-Service en PDF.

Le das el nombre de una escuela, su sitio web y si es un campus o una red. Propel busca las fotos, arma el PDF y una persona lo aprueba antes de entregarlo.

Por Andrés MoraV1 funcionando03.10.26

01Qué es Propel

Propel es un agente que genera la propuesta comercial TrustED Full-Service en PDF. Le dices el nombre de la escuela, su sitio web y si es un campus o una red de campus. Propel busca las fotos, arma el PDF y lo manda al chat para que una persona lo revise y lo apruebe.

La base son las 19 páginas de la plantilla. Además puede armar variantes: agregar las hojas de trato para redes (precios por número de campus, qué incluye, reportes de distrito y términos), poner una hoja donde lo pida la instrucción o crear una página a la medida con los bloques del sistema visual.

Está hecho con eve, el framework de Vercel para agentes: un agente es una carpeta de archivos (instrucciones, tools, canales, skills) que eve compila y despliega. Vive en Vercel y se usa por Telegram y por un canal de Scale CRM.

En la prueba con Aspire Public Schools pasaron unos 40 segundos entre el mensaje y el PDF de preview.

02Problema y objetivo

Problema

La propuesta se armaba a mano en Canva: duplicar la plantilla, cambiar el nombre de la escuela en cada página donde aparece, buscar tres fotos y exportar. Es lento y es fácil dejar un nombre viejo en alguna página.

Objetivo

Dar nombre, sitio web y modalidad, y recibir un PDF idéntico a la plantilla, sin tocar el diseño ni el texto.

Cómo sabemos que funciona

  • El PDF tiene las páginas de su receta y solo cambia lo que listan las secciones 3 y 6.
  • Pesa menos de 8 MB. Si pasa, el render se bloquea.
  • Ninguna propuesta se entrega sin que una persona la apruebe.
  • Del mensaje al preview pasa menos de un minuto. Medido: 15:03:42 el mensaje, 15:04:21 el PDF.
Regla central

El texto de los módulos fijos (pilares, testimonios, precios de planes, contrato) nunca se reescribe. Las hojas de trato aceptan texto del equipo, usan uno por defecto o, si se lo piden, el modelo propone uno, que queda marcado para revisión. Las cifras siempre las da el equipo.

05Flujo de una propuesta

Estos son los pasos, en orden. Los hace el agente solo, y la persona interviene para dar los datos iniciales, pedir cambios y aprobar.

  1. Datos. Si falta el sitio, o no queda claro si es un campus o una red, el agente lo pregunta antes de crear nada.
  2. Fotos. Primero el sitio de la escuela. La IA solo entra si el sitio no tiene nada útil (sección 7).
  3. Render. Se genera una versión nueva en cada llamada. Nunca se sobrescribe la anterior.
  4. Cambios. Si piden otra foto, se corrige solo ese espacio y se vuelve a renderizar.
  5. Entrega. Solo con aprobación humana (sección 8).

06Variantes de propuesta

Una propuesta es una receta (lista ordenada de módulos) que se puede ajustar para cada trato. El plan ajustado y el contenido de cada módulo se guardan en la propuesta, así que una versión nueva parte de lo último que se pidió.

Recetas

RecetaQué esNecesita
full-serviceLas 19 páginas de siempre.Nombre, sitio, modalidad, 3 fotos.
full-service-networkLo mismo más las dos hojas de red después de la página 5 (21 páginas).Además, las opciones de precio del trato.
GuardadasLas que el equipo guarda desde el chat con save_recipe (tabla propel.recipes).Lo que pidan sus módulos.

Hojas de red

Salen de las hojas que se hicieron a mano para Noble Schools, con el mismo diseño. network-pricing lleva hasta 3 opciones (número de campus y precio por campus) y calcula los totales. network-includes lleva servicios incluidos, reportes de distrito y términos, y toma el número de campus de la hoja de precios. Todo su texto tiene un valor por defecto, que es el de Noble con el nombre de la escuela.

El contrato toma el precio del trato

Si la propuesta lleva network-pricing, el contrato usa la opción recomendada (o la única, si hay una sola) en vez de la tarifa estándar de $2,500 por escuela. Cambian 4 puntos y nada más:

DóndeTexto con el ejemplo de Noble
Sección 3, alcance"…across 17 participating campuses at $1,500 per campus per month ($25,500 per month in total), as set out in the pricing of this proposal."
Sección 4, Base Service Fee"$1,500/month per campus for 17 participating campuses ($25,500/month in total). Changes to the number of participating campuses require a written pricing adjustment."
Exhibit A"Full Service Support, $1,500/mo per campus · 17 campuses"
Exhibit C, Base Fee"$25,500/month (in advance): 17 participating campuses at $1,500/month per campus."

Sin hojas de red el contrato no cambia. Con varias opciones y ninguna recomendada, la propuesta no se renderiza: no habría un precio que firmar.

Quién escribe qué

Páginas a la medida

Cuando un trato pide contenido que no cabe en ningún módulo, se inserta custom:<slug> donde lo pida la instrucción y se llena con un título y de 1 a 8 bloques del sistema visual: section, paragraphs, numbered, cards, panel, callout, terms y prices. No se diseña nada nuevo: los bloques son los mismos de las hojas de Noble y cada uno tiene límites de texto.

Reglas que se validan en código

  • Cada campo tiene un límite de caracteres. Si no se cumple, la tool dice qué campo y cuál es el límite.
  • Cada hoja con contenido se renderiza sola antes del PDF final y debe ocupar exactamente 1 página.
  • Solo una opción de precio puede ser la recomendada.
  • La palabra en coral del título (titleAccent) no puede repetirse dentro del título.
  • Nada se inserta entre la portada del contrato y el contrato: "antes del contrato" es antes de agreement-cover.

07Fotos

Cada propuesta tiene tres espacios de foto. Todo lo demás (logos, capturas de producto, fotos de TrustED) viene fijo con la plantilla.

EspacioPáginaMínimoCriterio
cover11200 px de lado largoEs la foto más visible del documento. Alumnos en actividad real, buena luz, horizontal, sin texto ni logos encima. Si ninguna llega al mínimo se genera con IA, porque una foto chica estirada se ve peor que una generada.
mission2800 pxAlumnos con docentes, si el sitio lo tiene (suele estar en /about).
centralized4800 pxCualquier foto de la comunidad escolar.

Reglas de las imágenes con IA

  • Pueden aparecer personas, pero nadie reconocible en primer plano: grupos, de espaldas, fuera de foco o a media distancia.
  • Sin texto, letreros ni logos.
  • Máximo 6 generaciones por propuesta, contando las regeneraciones. Al llegar al tope, la tool devuelve un error a propósito y el agente pide una foto al equipo.
  • No se usan fotos de stock. Una foto de stock con menores presentada como alumnos de la escuela es un riesgo que no se corre.

Una misma foto no puede ir en dos espacios: set_slot_photo lo rechaza. Cada candidata pasa por un modelo chico con visión (google/gemini-3.1-flash-lite) que descarta gráficos, logos, capturas, ilustraciones y fotos con texto encima, y describe lo que se ve para elegir qué va en cada espacio. Si el modelo falla, la búsqueda sigue con un filtro por el nombre del archivo. En las pruebas, la revisión visual acertó donde el nombre engañaba: aceptó fotos limpias llamadas "Blog-Cover" y descartó banners con nombres normales. Antes de entrar al PDF, cada foto se reduce al tamaño que ocupa (1600 px la portada, 1200 las demás) y se pasa a JPEG.

El filtro de la tool de búsqueda es de 600 px. Los mínimos de 1200 y 800 los aplica el agente siguiendo la skill photo-selection.

08Aprobación y entrega

La entrega pasa por una aprobación de eve (approval: always() en deliver_proposal). Mientras no se responda approve, la tool no corre y la propuesta no se marca como entregada.

Decisión

Se mantiene la aprobación de eve aunque cueste dos mensajes ("aprobado" y luego approve). Nadie entrega por error. Si el equipo prefiere uno solo, hay que quitar la aprobación para el canal de Scale, y eso se decide aparte.

El modelo no maneja links

En la primera prueba de Scale el link de descarga salió roto. La causa: render_proposal devolvía la URL firmada al modelo y el modelo la reescribía en su mensaje cambiando un carácter. La solución fue que las tools devuelvan solo la ruta (storagePath) y que cada canal firme el link y suba el archivo.

10Cómo se genera el PDF

Módulos y recetas

La plantilla está partida en módulos: los 15 de la plantilla base (uno por página, salvo el contrato, que fluye en varias), las 2 hojas de red y las páginas a la medida. Una receta es la lista ordenada de módulos que forma una variante. Crear una variante es escribir otra lista, no copiar páginas.

Cada módulo declara su id, título, descripción, cuántas páginas ocupa, qué espacios de foto necesita y, si acepta contenido, su esquema con límites y su texto por defecto. render_proposal pide solo las fotos que declaran los módulos del plan.

Reglas de diseño

  • Tamaño carta, 612 x 792 pt.
  • Tipografía: Manrope en títulos e Inter en cuerpo. Los títulos llevan letter-spacing de -1.
  • Iconos Phosphor. Sobre fondo claro, peso fill.
  • El duotono solo va en la foto de portada.
  • Las imágenes de Lead Generation y CMO Strategy usan objectFit: "contain" y fondo blanco: no se recortan.

Peso del PDF

Las capturas y fotos fijas de la plantilla se guardan en JPEG optimizado (template/full-service/optimized/, generadas con scripts/optimize-assets.ts): pasaron de 4.9 MB a 0.8 MB. El PDF base bajó de 7.5 MB a 2.9 MB, y una propuesta de red con página a la medida pesa unos 2.4 MB. El tope sigue en 8 MB.

Assets fijos

Fuentes, logos y capturas viven en Storage, carpeta _assets/. En Vercel el bundle no incluye archivos que se referencian por ruta, así que se descargan a /tmp la primera vez que una instancia los necesita. Si agregas un asset a la plantilla, súmalo a FIXED_ASSET_PATHS en react/assets.ts y corre npm run assets:upload. Si no, funciona en local y falla en Vercel.

Decisión

La plantilla se hizo en React con @react-pdf/renderer y no en HTML con Chromium. La versión HTML rompía las curvas de los iconos, apilaba mal las capas y desfasaba el texto por diferencias de fuente. react-pdf calcula el layout por su cuenta, sin navegador, y da el mismo resultado cada vez.

13Canales

Telegram

El bot es @trustedpropel_bot. Telegram entrega los mensajes al webhook /eve/v1/telegram con un secret token. Para agregar a alguien o a un grupo, se suma su chat.id a TELEGRAM_ALLOWED_CHAT_IDS.

Scale CRM

El equipo habla con Propel en un canal tipo Slack (#proposals), con hilos. Un hilo es una conversación y una sesión del agente, y puede producir varias propuestas. Si varias personas escriben en el mismo hilo, cada mensaje llega al agente como [Nombre] texto y Propel responde a cada quien por su nombre.

Contrato: Scale a Propel

POST https://propel-agent.vercel.app/cowork/message
Authorization: Bearer <PROPEL_TASK_WEBHOOK_SECRET>

{
  "messageId": "id estable del mensaje",
  "threadId":  "raíz del hilo (una sesión por hilo)",
  "channelId": "id del canal",
  "author":    { "id": "...", "name": "Andrés" },
  "text":      "Hazme la proposal de Aspire Public Schools...",
  "attachments": [{ "fileName": "...", "url": "https://...", "mimeType": "image/png" }]

Contrato: Propel a Scale

POST {PROPEL_SCALE_WEBHOOK_URL}   (la función propel-webhook de Scale)
Authorization: Bearer <PROPEL_STATUS_WEBHOOK_SECRET>

{ "threadId": "...", "kind": "typing" }

  • Scale entrega cada mensaje al menos una vez. Propel descarta repetidos con messageId.
  • La palabra approve se manda sin envolver. Las variantes en español (aprobado, aprobada, aprobar) las traduce el canal.
  • El link del adjunto dura 24 horas. Scale descarga el PDF a su propio Storage apenas lo recibe.
  • Si el hilo no existe en Scale, el webhook responde 404 y Propel no reintenta.

16Costos y rendimiento

18Repo y cómo correrlo

proposal-creator/
├─ agent/
│  ├─ agent.ts            modelo y dependencias externas del build
│  ├─ instructions.md     identidad y reglas del agente
│  ├─ channels/           telegram.ts, cowork.ts (Scale)
│  ├─ tools/              las 7 tools
│  ├─ skills/             photo-selection, school-name-variants
│  └─ lib/                db, supabase, scrape, aiImage, images, names, cowork
├─ react/                 la plantilla del PDF
│  ├─ pages/              el diseño de cada página
│  ├─ modules/            registro de módulos: datos, fotos y render
│  ├─ recipes.ts          recetas (variantes), planes y validación del contenido
│  ├─ blocks.tsx          bloques de las hojas de trato y páginas a la medida
│  ├─ optimized/ (en template/full-service) imágenes fijas en JPEG
│  ├─ buildProposal.tsx   arma el documento y lo renderiza
│  └─ theme, fonts, icons, components, assets
├─ db/migrations/         0001_init.sql, 0002_cowork.sql, 0003_plans.sql
├─ scripts/               upload-assets.ts, optimize-assets.ts, migrate.ts,
│                         render_variants.tsx (muestras), e2e_variants.ts (integración)
├─ evals/fixtures/        casos de prueba (PROUD Academy)
└─ docs/                  prompt de integración con Scale

Comandos

npm install
npm run dev                   # agente en local con eve
npx tsx react/render.tsx      # genera template/full-service/react-preview.pdf
npm run typecheck
npx tsx scripts/render_variants.tsx /tmp/muestras   # PROUD, campus único, Noble y hojas sueltas
npx tsx --env-file=.env.local scripts/e2e_variants.ts <proposalId con 3 fotos>
npm run assets:upload         # sube los assets fijos a Storage
npx eve deploy --non-interactive --yes

19Glosario

TérminoSignificado
eveFramework de Vercel para agentes. Compila la carpeta agent/ y la despliega.
ToolFunción que el modelo puede llamar.
SkillDocumento con criterios que el agente lee cuando le sirven.
CanalPor donde entra y sale la conversación (Telegram, Scale).
WebhookUna URL a la que otro servicio hace POST cuando pasa algo.
OutboxTabla de mensajes pendientes de enviar, con reintentos si falla la entrega.
URL firmadaLink temporal a un archivo privado, con un token que caduca.
RLSRow Level Security de Postgres. Sin policies, nadie accede salvo el rol de servicio.
MóduloUna pieza de la propuesta: una página, o el contrato que ocupa varias.
RecetaLista ordenada de módulos que forma una variante de propuesta.
PlanLa receta ajustada para una propuesta concreta.
Página a la medidaMódulo custom:<slug> que se arma con bloques del sistema visual.
HiloConversación en Scale. Equivale a una sesión del agente.
